# The Keylight story

## Prologue

**What it is.** Two native apps that turn a screen into a controllable key light for video
calls — one for Apple TV, one for the Mac.

**Who it's for.** Anyone who takes calls in front of a big screen and doesn't want another
piece of hardware on the desk. It was built for a 55" TV sitting directly opposite the desk,
and then extended to the Mac that does the actual calling.

**The problem it solves.** Webcams are starved of light, and the usual fix is a dedicated
panel on an arm — one more thing to buy, mount, power and look past. But there is already a
large, dimmable, colour-accurate emitter pointed straight at the subject's face. The gap is
that a TV showing a white image is a crude light: fixed colour, fixed shape, and no way to
adjust it without leaving the call.

**Why it matters.** Getting this right is mostly colour science and shape, not brightness.
A light that sits on the Planckian locus matches the room instead of fighting the camera's
auto white balance, and a shaped light models a face instead of flattening it.

## Chapter 1 — A light you can aim, and the bug that only exists on real hardware

*2026-11-02 · iteration 01*

**The goal** was a tvOS app controllable entirely from the Siri Remote, then a Mac companion,
then this repo made public with a landing page worth reading.

**What we tried.** The tvOS app came first: colour temperature converted properly through the
Planckian locus rather than a naive orange ramp, six light shapes, and a control scheme where
up/down is always brightness and left/right drives one assignable dial. The Xcode project was
hand-written as a file-system-synchronized target, and the layered tvOS parallax icon was
generated by a Python script that writes PNGs with nothing but `zlib` and `struct`.

**What worked.** The colour maths was verified numerically before anything was deployed —
6500 K lands on D65 exactly as it must, 2700 K matches a tungsten bulb, and the warm-to-cool
ramp is strictly monotonic. State round-trips through `Codable` losslessly. The app built
clean for `appletvos` in Debug and Release with zero warnings, and deployed to the Apple TV.

**What broke.** Two things, and the second one matters.

The first was mundane: `actool` refused to compile the tvOS app icon with
*"No available simulator runtimes for platform appletvsimulator"* — on a device-only build,
with a perfectly valid asset catalog. The tvOS Simulator runtime simply wasn't installed.
`xcodebuild -downloadPlatform tvOS` fixed it.

The second was the real lesson. On the Apple TV the light rendered as a **solid white screen**
the moment the control panel closed. Every simulator check had passed. The cause was the
invisible full-screen `Button` used to catch remote input, whose label was
`Color.white.opacity(0.001)`: tvOS brightens a focused button's label while a finger rests on
the Siri Remote touchpad, compositing that near-zero white to full white across the entire
display. No simulator reproduces it, because no simulator has a capacitive touchpad to rest a
finger on. The report that pinned it was *"panel open looks right, panel closes goes white"* —
and the catcher existed only while the panel was closed.

**Decisions and why.** The fix was three-part: a custom `BareButtonStyle` that renders only the
label (the built-in `.plain` style still applies the platform's focus treatment, and
`focusEffectDisabled()` does not fully suppress it), a `Color.clear` label, and shrinking the
catcher from full-screen to 60 pt in a corner so no focus decoration can physically reach the
light. The same session found a quieter sibling bug: `@Environment(\.isFocused)` reports the
nearest focusable *ancestor*, so a view that applies `.focusable()` to itself always reads
false — which is why the panel's value rows adjusted correctly but never highlighted.

The Mac app was kept as a **separate Xcode project** with its own copy of `ColorScience.swift`.
Sharing the file would have meant restructuring the tvOS target that had just been deployed and
verified; duplicating ~100 lines of verified maths was the cheaper risk. That trade is written
down in the README so it doesn't become an accident.

On the Mac the interesting decision was window stacking. "Behind all apps" was the request, and
it works — but whatever window you're in covers the light. So an **In front** mode was added:
the light floats above everything with `ignoresMouseEvents` set, so clicks pass straight
through. That only works because the shaped layouts leave the centre of the screen fully
transparent, which is also why **Two Panel** is the Mac default. The machine ended up switched
to exactly that combination.

**Lessons.** Simulators verify logic, not hardware interaction surfaces — touchpad hover,
focus treatments and display behaviour all need the real device. And a precise bug report
("it goes white *when the panel closes*") localises a defect faster than any amount of
re-reading the renderer.

## Chapter 2 — Same code, second Mac, newer Xcode

*2026-11-02 · iteration 02*

**The goal** was to build the Mac app on the second Mac in the two-Mac setup and install it
there. The first `xcodebuild` failed immediately, not because of the code but because
`xcode-select` on this machine still pointed at the Command Line Tools. Rather than change a
system setting, the build ran with `DEVELOPER_DIR` pointed at `/Applications/Xcode.app` for
the one command. This Mac turned out to be on Xcode 27.2, the version chapter 1's standards
check had flagged as current but out of reach on the first Mac. The prediction held: the
project built in Release on Xcode 27 without a single change to a source file or build
setting. Keylight went into `/Applications`, launched, and put a light window on both
displays with the control box in its corner. The one thing that didn't work was the
screenshot. This Mac hasn't granted Screen Recording to the terminal, so `screencapture`
couldn't read the window, and no image was faked in its place.

**Lesson.** Pinning `SWIFT_VERSION = 5.0` and minimal concurrency checking let a major Xcode
upgrade go through without any code changes.
